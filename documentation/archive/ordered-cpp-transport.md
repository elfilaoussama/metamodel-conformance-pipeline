# Ordered compiler transport v2 — prospective contract

The diagnosed cause is projection of a compiler invocation into separate lists:
undefinitions and include categories disappear and cross-kind order is lost.
The repair keeps one ordered typed operation sequence. P0 and schema remain fixed.

The population is source declarations in one selected build configuration, not
effective lookup or all configurations. Source-root translation units are targets;
included files are consumed support inputs. Generated/external paths unavailable
at the observation root are unsupported, not silently omitted. Derived P0 views
remain distinct from native lookup. Historical formula recovery remains open.

v2 context rows declare `ordered-v2`. Legacy `.` rows remain readable; they retain
their historical grouped argument interpretation. v2 preserves define, undef,
include, system-include, quote-include, after-include, std and supported flag order.
Paths resolve against compilation-database directory, then normalize to source
root. Compiler wrappers, response files, implicit/default language standard,
unknown semantic flags, inaccessible paths, conflicts and empty databases reject.
Supported flags are explicitly bounded; acceptance is not universal build support.
Original directory/argv and normalized consumed rows are retained in provenance.
The consumed ordered sequence is fingerprinted in observation input identity.

Publication validates the whole database first. Failure leaves an empty manifest
and no provenance; successful manifests publish by atomic rename. A manifest is
the completion marker, published after its provenance. Readers must not use output
from a failed provider. Each corridor output directory is created exclusively;
provider/domain/execution/formal decisions are separate in an atomic report.
Direct analyze invalidates an old capsule before observation begins.

## Frozen acceptance campaign

Four families, seven positive variants and four rejection variants, no expansion:

1. Macro order: define→undef expects double; undef→define expects int.
2. Includes: user-before-system expects int; reverse user order expects double;
   relative directory with spaces expects double.
3. Standards/flags: C++14 expects int; C++17 with -fno-exceptions expects double.
4. Rejections: unknown semantic flag; conflicting contexts; empty database;
   malformed later entry after a valid one. Each starts with a stale output and
   must leave no usable manifest/provenance.

Positive fixtures each contain Sample.own with one parameter. Exact source facts
are expected separately from formal outcomes: ownership, namespace and
static/abstract separation conform; other eight decisions are NOT_EVALUATED
(no complete hierarchy). Compare raw facts, XMI, exact encoding, all decisions,
full witnesses, full-model reference and fresh-process replay. Native Clang with
original argv is independent of transport, not independent of Clang itself.

Per variant provider180s/analysis30s/reference30s/replay20s/oracle10s; campaign
1200s including setup/retention. Focused fail-first build180s and normal build420s
are separate costs. Frozen rc.8 counterexample and expected rejection policy are
retained unchanged. New profile expectations apply only to the new producer.

The first normal build hit its 420s ceiling after 28 successful test classes,
without a reported semantic failure. WSL load was approximately 23 and several
fresh background system services were active. Its evidence is retained. A single
final-input retry is declared at 900s, separate from the unchanged 1200s campaign;
no correctness/evidence requirement is weakened to meet the earlier wall time.

The compilation database's directory is authoritative for relative operands;
multiple command objects may describe one source. This follows the pinned
[Clang 14 format](https://releases.llvm.org/14.0.0/tools/clang/docs/JSONCompilationDatabase.html).
Equal consumed contexts may collapse; conflicting contexts reject. Provenance
retains every original invocation, including duplicates and driver-only options.

This milestone settles the immediate contract, not all W01 publication obligations.
Unavailable original formula bodies/revisions, independent identity, direct runtime
instances, condition-selection provenance and covariance correspondence remain
explicitly open in the master claim register. Cross-language capabilities remain
unchanged. Provider/toolchain compatibility and generated-input closure require W04.
Successful transport is not a certificate for compiler frontend correctness.
