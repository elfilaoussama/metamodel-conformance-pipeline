# Replaceable rule profiles

The formal conditions are variable. The reusable instrument is the path from
declared input worlds to observations, evidence-qualified evaluation, witnesses
and reproducible records.

## Current baseline

The bundled regression/research profile contains eleven checks tracing the
manuscript's O-02 through O-09 conditions. It does not define all object-oriented
semantics. O-01 identity preservation is a bridge-integrity question, and runtime
object claims are outside a repository-only observation.

Metadata is registered in `src/main/resources/invariants/registry.json`.
Formal witness functions are defined in
`src/main/resources/alloy/invariants.als`. The web inspector reads the recorded
metadata, prerequisites, decisions and witness tuples. It does not maintain a
second hard-coded list of scientific verdicts.

## Add a condition responsibly

1. Document the theoretical statement, scope and derivation independently from
   the implementation.
2. Identify the observed concepts and completeness requirements it needs.
3. If those concepts already exist, add a versioned registry entry and formal
   witness definition. Do not add invariant-specific observer branches.
4. If concepts are absent, define a versioned contract/adapter extension or mark
   the condition unsupported. Do not infer missing semantics from a name.
5. Specify independent positive, negative and unknown source controls and the
   expected witness tuples.
6. Validate full evaluation, any proposed partitioning/reuse and capsule replay
   with the exact new profile.
7. Record the new rule/registry/producer identities. Preserve the old experiment.

## Distinguish engine extensibility from interface features

The engine can evolve its formal resources through reviewed builds. The current
web interface executes only its configured matching engine's bundled profile.
It does not offer a rule editor, arbitrary profile upload or theoretical-condition
translator. Documentation must not present those as implemented features.

A new condition over existing facts should require no unrelated provider or
presentation change. A new semantic concept can legitimately require coordinated
schema and consumer updates. Record that boundary and validate it explicitly.
